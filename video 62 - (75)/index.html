Pyramid of Doom :

  1. ab callbacks ek ke andar ek itne zyada ho jaate hain ki code samajhna mushkil ho jata hai, use Pyramid of Doom kehte hain.
  2. JavaScript mein Pyramid of Doom tab hota hai jab hum multiple callbacks ko ek ke andar ek likhte jaate hain.
  3. Ismein problem kya hai?
  4. Dekho, ek callback ke andar doosra callback hai, uske andar teesra callback hai.
  5. Jaise-jaise callbacks badhte jaate hain, code right side mein badhta jaata hai.

  6. Isse kuch problems hoti hain:-

    1. Code samajhna difficult ho jata hai.
    2. Debugging karna difficult ho jata hai.
    3. - Code manage karna difficult ho jata hai.
  7. Isi ko Pyramid of Doom kehte hain.

  8. Is problem ko solve kaise karein?

  9. Iske liye JavaScript mein Promises aur Async/Await use karte hain.

Short mein yaad rakho: 

- Callback: Ek function ko doosre function mein pass karna.
- Callback Hell: Bahut saare nested callbacks.
- Pyramid of Doom: Callback Hell ki wajah se code pyramid jaisa dikhna.
- Promises: Nested callbacks ki problem ko reduce karna.
- Async/Await: Asynchronous code ko aur easy banana.

Promise :

  1. The solution to the callback hell is promises.
  2. A Promise is a "Promise of code execution". the code either execute or fails, in both the cases the subscribers will be notified.
  3. JavaScript mein Promise ek aisa object hai jo future mein kisi asynchronous operation ke complete hone ya fail hone ko represent karta hai.

    4. Ex :

    Maan lo tumne online pizza order kiya.

  4. Abhi pizza tumhare paas nahi hai, lekin restaurant tumhe promise karta hai ki pizza deliver karega.

    5. Ab 3 possibilities hain:

    1. Pending: Pizza abhi ban raha hai.
2. Fulfilled: Pizza successfully deliver ho gaya.
3. Rejected: Pizza order cancel ho gaya. 

JavaScript Promise bhi isi tarah kaam karta hai.

resolve() :

  1. resolve() Promise ko successfully complete (Fulfilled) karta hai aur successful result provide karta hai

reject() :

  1. reject() Promise ko fail, error (Rejected) karta hai aur failure ka reason provide karta hai.

.then() :

  1. .then() Promise ke successfully resolve hone par execute hota hai aur resolve ki value receive karta hai.

.catch() :

  1. .catch() Promise ke reject hone par execute hota hai aur rejection ka reason receive karta hai.

promises Chaining :

  1. Jab hum ek Promise ke .then() ke andar se doosra Promise return karte hain aur uske baad next .then() lagate hain, toh ise Promise Chaining kehte hain.
  2. Ek kaam complete hone ke baad doosra kaam execute karna, phir doosra complete hone ke baad teesra kaam execute karna.

Promise API :

  1. Promise.all() :

    1. Promise.all() multiple Promises ko ek saath handle karta hai. Jab saare Promises resolve ho jaate hain, tab ye result return karta hai. Lekin agar ek bhi Promise reject ho gaya, toh ye reject ho jata hai.
    2. Yaad rakho: Saare resolve hone chahiye, ek bhi reject hua toh Promise.all() reject ho jayega.

  2. Promise.allSettled() :

    1. Promise.allSettled() tab result deta hai jab saare Promises settle ho jaate hain, chahe resolve ho ya reject.
    2. Yaad rakho: Koi bhi Promise reject ho, phir bhi ye sabhi Promises ke results deta hai.

  3. Promise.race() :

    1. Promise.race() multiple Promises mein se jo sabse pehle settle hota hai, uska result return karta hai
    2. Yaad rakho: Jo sabse pehle resolve ya reject hoga, race() usi ka result dega.

  4. Promise.any() :

    1. Promise.any() multiple Promises mein se jo sabse pehle successfully resolve hota hai, uska result return karta hai.
    2. Promise.any() rejection ko ignore karta hai jab tak koi Promise successfully resolve na ho jaye. Agar saare Promises reject ho jaayein, toh AggregateError deta hai.

  5. Promise.resolve() :

    1. ye ek already fulfilled Promise create karta hai.
    2. Yaad rakho: Directly fulfilled Promise create karna ho toh Promise.resolve() use karte hain.

  6. Promise.reject() :

    1. ek already rejected Promise create karta hai.
    2. Yaad rakho: Directly rejected Promise create karna ho toh Promise.reject() use karte hain.
